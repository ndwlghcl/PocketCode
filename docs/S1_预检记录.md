## 环境注意事项（S1 实现与诊断提示要用）

1. **Windows 防火墙三个配置文件当前均为关闭**（沿用任务书 §E 提到的现状）。
   S1 实验期间可维持；进入 S2 读写真实文件前必须重新启用，并只给
   PocketCode 放行所需端口/专用配置。诊断界面应能显示防火墙状态提醒。
2. **电脑端有代理软件**（TUN 虚拟网卡 `vgate0` = 172.30.250.85）。出站代理
   对"手机→电脑"入站无碍，但 S1 诊断流程应把"电脑代理"列为连接失败的
   排查项之一。
3. **手机端有机场代理**（手机状态页显示的 172.19.0.1 是其虚拟网卡，不是
   局域网地址）。本次测试手机代理开启状态下仍访问成功；若后续遇到手机
   侧超时，第一步排查项是"临时关闭手机代理"。
4. 电脑上同时存在 VirtualBox / VMware 虚拟网卡，管理窗口展示"局域网地址"
   时可能出现多个候选地址——S1 手动连接页要允许用户直接修改/输入 IP，
   不强信自动探测。
5. 已知虚拟网卡噪声清单（诊断页可参考过滤/标注）：vgate0（代理 TUN）、
   VirtualBox Host-Only（192.168.56.1）、VMware VMnet8（192.168.100.1）、
   Windows 移动热点适配器（192.168.137.1，当时误开着电脑侧热点）。

## 对 S1 的影响

- 手动 IP + 「测试连接」方案已验证可行，mDNS 不作为依赖（符合架构文档 §3.2 预案）。

  「测试连接」按钮、在线/离线状态显示、超时/拒绝连接等失败原因区分。

  在 S2 阅读器实现时纳入（S0 演示界面先保证旋转不崩溃）。
