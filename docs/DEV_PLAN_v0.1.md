# PocketCode 给 GLM 的开发任务书 v0.1

**依据**：《PocketCode 产品需求文档 v1.1》和《PocketCode 技术架构设计 v0.1》。  
**产品当前阶段**：尚未实现；此文为任务划分，不代表功能已经开发成功。  
**协作原则**：先合同后实现、先只读后写入、先真实 APK 后美化、每阶段可运行且可验收。

## A. GLM 协作制度（必读）

- 维护 **一个主仓库**。先由一个「主集成对话」提交 `docs/`、`contracts/openapi.yaml`、workspace 骨架，然后冻结 `v1` 语义。
- 并行 GLM 对话只认合同，分别负责：① 后端文件与安全；② Windows 管理界面；③ Android 手机客户端；④ 测试与集成。若实际没有共享同一个仓库，不要并行直接写同一目录，改为顺序提交补丁由主集成合并。
- **文件所有权**：后端只改 `desktop/pocketcode/{server,services,storage,security,discovery}`；Windows UI 只改 `desktop/pocketcode/gui`（通用 `main.py` 归主集成）；手机端只改 `mobile`；合同由主集成更新，其他人提出变更请求不擅自修改。
- 每个任务必须包含：代码 + 自动化测试 + 运行命令 + 修改文件清单 + 已知限制 + 可手动执行的验收步骤。
- **不允许**“临时跳过配对鉴权，让文件接口裸奔”进入可验收版本；默认不扫描电脑整个磁盘；不为了赶进度重构用户现有 Agent 仓库；不把测试成功描述成真实设备成功。
- 重大偏离架构时先写 `docs/decisions/ADR-xxxx.md` 记录理由、兼容性和迁移方案；不让多个 GLM 各自选型。

## B. 阶段与交付顺序

| 阶段 | 开发目标 | GLM 自动验证 | 用户在真实设备上的验收 |
|---|---|---|---|
| S0 · 基础骨架 | 统一仓库、OpenAPI、Windows 程序骨架、Android APK 空壳 | Windows 启动/退出；APK 编译通过；合同校验 | Windows 能开管理窗口、托盘存在；手机能安装/打开 PocketCode |
| S1 · 热点连通性实验 | 本地 `/v1/health`、手动 IP 诊断（**无文件访问**） | 后端单元测试，Android 请求状态与错误提示 | 手机开热点、电脑连热点，APK 显示与电脑连通 |
| S2 · 安全配对 + 只读闭环（对应 PRD M0） | 授权项目、证书身份、二维码配对、项目树与文件读取、自动发现基础、读取缓存 | token/越界校验、合同测试、Fake API UI 测试 | 手机上看真实代码；电脑保存后的文件手机刷新可见；未配对不可读取 |
| S3 · 可日用编辑（PRD M1） | 手机编辑、离线草稿、版本冲突、原子写入、文件新建删除、回收区 | 编码/冲突/恢复/权限/并发测试 | 手机修改电脑文件；断网多草稿保留；重连不自动覆盖 |
| S4 · 提升体验（PRD M2） | 搜索、大纲、跳转、Python 诊断、Git Diff、多文件分享 | 自动化测试与性能基线 | 手机使用红色波浪线、搜索、复制/分享等能力 |
| S5 · 高阶（PRD M3） | 智能关联、补丁导入、条件具备才做 ChatGPT 直连 | 安全与可回滚测试 | 用户批准前绝不对电脑原文件自动动手 |

**关键要求**：不允许跳过 S1 真机网络实验，直接让 GLM 宣称 S2 可用。S2 后才把“自动连接成功率”作为真实环境质量目标。先开放可安全读取的最小集合，再做完整功能。

## C. 首批可以直接分配的 4 个任务

### 任务 0 / 主集成 GLM：初始化仓库与接口合同

**目标**：可合并的工程骨架，而不是功能堆砌。

**执行要求**：
1. 按架构文档创建 monorepo；Windows `pyproject.toml`、Android `package.json`、Capacitor Android 工程、基本 README。
2. 制定 `contracts/openapi.yaml`（至少 health、配对、项目、manifest、读取），明确 token、路径编码、版本、错误、文件大小限制、项目 id，不接受客户端和后端分别编造返回格式。
3. 添加合同验证脚本、后端 pytest 基础、手机端 TypeScript 类型检查与构建命令，准备 fake JSON fixtures。
4. 提供 `scripts/` 下适用于 Windows PowerShell 的一键启动/打包脚本；不要要求用户每次手动修改源码填 IP。
5. 提供已知依赖版本、许可证和 Debug APK 构建环境说明。将来再做正式安装包签名/分发。

**验收**：主仓库基础构建成功，Windows 管理窗口能启动，Android debug APK 可安装；合同可被机器校验。此时**不要求真实代码访问**。

### 任务 1 / Windows 后端 GLM：只读文件服务与最小安全边界

**输入**：合同版本 v1，不自行定义 API 响应字段。

**执行要求**：
1. 配置授权项目存储、逻辑 project_id、只读项目列表与 manifest 生成，排除依赖与密钥相关目录，缓存文件元数据。
2. 实现只读文件接口、UTF-8/常见编码处理、BOM/CRLF 元数据、内容 hash 版本、大小/二进制防护。
3. 实现授权范围校验、防目录穿越/符号链接/junction 越界；所有文件接口必须在可信配对鉴权后可访问。
4. 实现 `/v1/health` 最小响应，日志脱敏，错误码与 HTTP 状态严格对齐合同。
5. 合同测试、pytest 边界测试；不实现编辑、删除及 AI 直连。

**验收**：对授权目录可读；对越界/未配对的请求必须拒绝；真机验证前不声称手机已连通。

### 任务 2 / Windows UI GLM：管理窗口、托盘与启动生命周期

**输入**：架构文档约定的 App Controller 接口（主集成先建空实现或 stub）。

**执行要求**：
1. PySide6 管理界面含「连接状态、已授权项目、配对手机、服务设置、诊断」五区；**不要做代码编辑器**。
2. 可通过原生文件夹选择器添加/移除授权项目；用户有意识地确定访问范围。
3. 最小化/关闭窗口不退出，托盘右键可打开、暂停服务、退出；Windows 登录自启可选、默认不开关开机休眠策略。
4. 显示二维码配对、连接诊断、手机撤销授权；证书和配对逻辑由后台服务实现，UI 只调用接口。
5. 确保 UI 主线程不被 server 或目录扫描阻塞；退出能彻底结束监听端口。

**验收**：Windows 11 上不需要浏览器管理项目，关闭窗口后服务仍在，托盘退出后端口停止监听。

### 任务 3 / Android GLM：APK 与只读浏览最小闭环

**输入**：已冻结的 OpenAPI + fixtures。没有可用后端时先对 mock 实现 UI。

**执行要求**：
1. 使用 React + TypeScript + Capacitor 生成真正可安装 APK；应用包内置本地前端资源，不从电脑 HTTP 页面加载 UI。
2. 启动始终进入项目列表；项目和文件最近阅读仅小标记；**文件夹先、文件后，各自名称排序**；进入项目默认根目录。
3. GitHub 风格逐层浏览 + 将来可切换 VS Code 树视图的组件边界；未缓存文件离线仍显示文件名、点击说明需联网。
4. CodeMirror 6 只读阅读页：高亮、视觉折行默认开启、行号、返回与阅读位置保存。编辑暂不做。
5. 实现连接管理的手动地址测试、自动重连 UI 与离线标识；之后添加扫码、可信设备、NSD 自动发现与安全连接，不要把 mDNS 可用视作确定事实。
6. 本地持久化目录树和已打开文件正文；离线冷启动可看上次缓存，不要求电脑在场。

**验收**：安装 APK 后进入项目列表、能离线看目录结构；S2 时能读取真实电脑文件。编辑器显示超长行不改原始换行。

## D. 跨模块集成（一个 GLM 主集成对话负责）

- 维护 `contracts/openapi.yaml` 为唯一真源；后端 OpenAPI 应与该合同自动比对，移动 TS 类型从合同生成。
- 集成顺序：health → 配对 → 项目列表 → manifest → read → offline cache → edit/write → trash。每条链路必须先跑通，再继续下一条。
- 多 GLM 并行不能让两人改 `mobile/src/api` 或 desktop `main.py`。公共结构由主集成统一合并。
- 凡改动文件 API、错误码、认证或数据格式，必须更新合同、fixture、后端测试和手机端类型；不得只改某个端。
- 每阶段给用户一份简明《测试卡》：前置操作、明确要点的按钮或地址、预期结果、失败时需要的截图/日志位置，以及恢复原状态的方法。绝不要求用户理解代码才能测试。

## E. 用户首次要做的真实设备测试（S1）

1. GLM 在 Windows 电脑启动 PocketCode 管理程序，UI 仅显示可访问的局域网地址、监听端口和 `health` 状态；不开放真实项目。
2. 手机打开热点，Windows 11 电脑连上手机热点。GLM 给出一份 APK 安装包（允许系统询问安装权限），在手机安装。
3. 手机打开 APK → 连接诊断 → 自动填入上次地址或手动输入 GLM 从电脑界面给出的当前地址 → 点「测试连接」。
4. 成功应显示「已连接测试服务」，失败区分超时、拒绝连接、权限未授权等情况；截取诊断信息交给 GLM。
5. 断开热点后显示离线；重新连接后可重试成功。此阶段没有真实文件传输，所以不会误改代码。

**安全提醒**：用户之前关闭了 Windows 防火墙，S1 网络实验可用这个环境做诊断；准备读写真实文件前须重新启用防火墙，并只给 PocketCode 必需的私有/受信任网络规则放行。测试不可要求关闭 TLS 验证或长期关闭系统防护。

## F. 给主集成 GLM 的首条指令（可直接复制）

> 你是 PocketCode 项目的主集成开发者。请把《PocketCode 产品需求文档 v1.1》《PocketCode 技术架构设计 v0.1》《PocketCode 给 GLM 的开发任务书 v0.1》视为完整输入。先完成任务 0（基础骨架与接口合同），不要直接实现所有产品功能。用户需要 Windows 11 独立管理程序、Android APK，手机热点局域网运行；Windows 仅管理不浏览编辑代码；手机承担阅读编辑。所有返回数据使用统一 OpenAPI 合同，给出可执行构建与验证命令、修改文件列表、测试结果及未验证的真机事项。遇到文档技术判断与现实冲突时说明原因并在 ADR 记录，不擅自改变产品要求。先保证 Windows 管理窗口和 Android 空 APK 都能真正构建，再开始 S1 `health` 连接实验。

## G. 后续开发不需要用户先决定的事项

- 代码分层、线程/异步模型、OpenAPI 字段精度、缓存仓储实现、依赖版本、容错重试、测试框架、模块分配、调试日志分级——主集成 GLM 决定细节并留痕。
- **需要用户介入**的仅是真机测试、电脑授权目录选择、配对与危险写入确认、产品体验是否符合此前讨论；没有必要要求用户从后端框架列表里做技术选型。
