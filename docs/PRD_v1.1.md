# PocketCode 产品需求文档（PRD）

**版本：** v1.1（需求讨论稿；合并 10 月 24 日后续决策）  
**日期：** 2026-10-24  
**状态：** 已确认需求汇总；尚未进入实现  
**定位：** 手机优先、局域网连接、可离线使用的电脑本地代码工作台

> **核心愿景：** 电脑上写代码，不必推送 GitHub；躺下打开手机，就能看电脑里的最新代码、直接编辑，必要时方便地把代码交给 ChatGPT 讨论。PocketCode 不是缩小版 PyCharm，也不以运行付费 AI 为前提。

**v1.1 变更记录（用户确认）：** 正式入口改为 Windows 独立管理程序 + Android APK；Windows 端只负责管理而不提供代码编辑；Android 每次启动进入项目列表，进入项目默认根目录；文件夹排前、文件排后、各自按名称固定排序，最近阅读只标记不改变顺序；离线保留项目树和未缓存文件名；在线自动更新授权范围内完整目录元数据，文件内容按需缓存；一次配对可访问全部已授权项目，后续新增授权项目自动出现。

## 1. 产品目标与优先级

用户明确给出的优先级，不可在开发时重新排序：

| 优先级 | 核心目标 | 完成标准 |
|---|---|---|
| P0 · 第一 | 手机上直接看电脑本地代码 | 不上传 GitHub；浏览电脑授权项目与真实文件；连接时看到磁盘最新保存版本 |
| P1 · 第二 | 手机上修改电脑本地代码 | 支持编辑、新建、删除；确认保存后直接写入电脑原文件；可撤销与恢复 |
| P2 · 第三 | 不推送仓库也能方便地让 ChatGPT 看代码 | 支持片段、单文件、多文件、智能关联、Git Diff 等分享方式；若不能直连，手动分享也好用 |
| P3 · 第四 | 让 ChatGPT 像电脑 Coding Agent 一样直接改代码 | 作为长期目标，依赖可用的连接方式；首版不承诺当前 Android ChatGPT 可直接读写电脑 |

**硬约束：** 免费或无需持续订阅；主要通过手机热点组成的局域网连接；不需要异地访问；不依赖 GitHub 推送；电脑端需开机并运行服务才能访问最新文件。

## 2. 使用场景与关键流程

### 2.1 睡前继续阅读

电脑上的 PyCharm 保存代码 → 手机打开 PocketCode APK，默认进入项目列表 → 自动连接电脑 → 用户打开项目（默认根目录）和文件 → 阅读最新的磁盘内容。关闭 PyCharm 不影响访问；电脑休眠、关机或断网时转为离线查看缓存。

### 2.2 手机编辑并同步

手机进入已打开文件 → 切换编辑模式 → 修改代码 → 本地自动保留草稿 → 用户主动点击「保存到电脑」 → 服务确认源文件未变化 → 写入电脑原文件。若电脑版本已变化，不能静默覆盖。

### 2.3 离线改着玩

电脑断开 → 手机打开上次缓存的代码 → 从文件或已有草稿创建「实验副本」 → 给不同草稿命名并继续修改 → 不必同步电脑。电脑恢复连接后，用户自行选择对比、合并、覆盖、另存或继续保留草稿。

### 2.4 躺着把代码交给 AI

手机选择一段代码、文件、相关代码、多个文件或 Git Diff → 预览将要分享的内容和结构树 → 复制文本或使用系统分享 → 在现有 ChatGPT 对话中讨论。未来若存在可靠的直接连接能力，再允许 AI 按需读取与经确认后写入。

## 3. 客户端与连接体验

### 3.1 应用形态

- **已确认：** 先开发可在手机浏览器使用的网页核心，之后封装 Android APK；两者共享主要 UI 与逻辑。
- 网页版先验证局域网远程浏览、编辑和保存；APK 需重点验证离线启动、草稿存储及 Android 分享。
- 可以选择 PWA / Capacitor 等实现方式，但它们是技术建议，不是用户要求指定的框架。普通局域网 HTTP 页面不能直接假定具备可靠的 PWA 离线安装能力；部署和 APK 阶段应专项验证。

### 3.2 电脑连接

- **主要网络：** 手机开启热点，Windows 电脑连接手机热点；两设备处于可互访的局域网时直连，原则上不需要 Tailscale、服务器订阅或外网。
- **首次使用：** 电脑端添加授权项目或工作区；手机扫描电脑显示的配对二维码，完成一次配对后即可访问该电脑**当前及以后新增的全部已授权项目**，无需逐项目授权。
- **日常使用：** 打开手机应用自动尝试连接已配对电脑；不要每次要求输入 IP、端口或手动点击电脑端同步。
- 提供连接状态：已连接 / 重连中 / 离线；同时提供手动刷新入口。
- 连通性受热点隔离、防火墙和地址变化影响；无法自动发现时提供明确的手动连接和诊断方式。

### 3.3 Windows 后台服务

- Windows 登录后自动启动 PocketCode Server，默认最小化到系统托盘，不弹出无关窗口。
- 关闭 PyCharm 不影响服务；电脑休眠或关机后不可读取磁盘最新内容，手机使用缓存。
- 托盘可查看状态、管理授权项目及已配对设备、暂停 / 退出服务。
- 无手机连接时保持低资源消耗，不频繁全量扫描项目；不默认阻止电脑休眠。

### 3.4 项目变化的发现

- **手机连接时自动检查**：更新已授权项目列表、完整目录结构元数据、文件新增 / 修改 / 删除状态；文件正文仍按当前项目的缓存策略处理，默认按需缓存。
- **连接期间**：尽量及时感知电脑端保存后的文件变化；正在编辑的文件只提示冲突，不覆盖草稿。
- 手机可主动点「同步 / 刷新」以重新读取电脑，不需要电脑端先点同步。
- 自动发现新增项目的范围仅限用户预先授权的工作区根目录；其他位置的新项目须重新授权，不扫描电脑全部私人文件。

## 4. 文件浏览、阅读与导航

### 4.1 浏览模式

- **默认 GitHub 风格**：一次浏览一层文件夹，进入目录、返回上级，适合手机小屏。
- 可切换 **VS Code 风格目录树**：多层目录展开 / 折叠。
- 两种模式共享当前项目、已打开文件和阅读位置；切换不会丢状态。
- 提供最近打开、文件名搜索、项目全文搜索、函数与类名搜索。结果可预览上下文、显示路径和行号、点击定位。
- 离线搜索只覆盖已缓存内容，必须清楚标注缓存来源及同步时间。

### 4.2 阅读器

- 代码阅读和编辑均**默认开启视觉自动折行**：不修改源文件的换行、缩进和行号；允许关闭折行切换横向滚动。
- 常见语言支持语法高亮（Python、Java、JavaScript、TypeScript、JSON 等）；首版高级诊断优先 Python。
- 具备逻辑行号、代码折叠、文件内搜索与替换、跳转行号、字号与主题设置、滚动位置记忆、选区复制。
- 当前文件「代码大纲」展示类、方法、函数及所在行，可从底部抽屉选择并跳转。

### 4.3 避免误触的符号导航

- **普通单击代码不跳转定义**，避免在手机滚动和选择文字时误触。
- 阅读模式长按选中符号后，主动选择「跳转定义 / 查找引用 / 调用关系 / 复制符号」。
- 编辑模式从光标所在符号触发「代码操作」，不抢占普通光标定位。
- 跳转后可以返回原文件及准确阅读位置；查不到定义时明确说明，不随意跳同名函数。
- 完整跨文件语义引用与调用图可分阶段增强，Python 动态行为可能无法静态识别。

### 4.4 多文件操作

- **已确定交互**：单文件全屏阅读 / 编辑，顶部点击当前文件名打开「已打开文件」抽屉，不使用拥挤的横向标签栏。
- 每个打开文件分别保留滚动位置、光标、选区、未保存修改；抽屉按最近使用排序且可搜索。
- 关闭已打开文件不等于删除或丢弃草稿；跳转历史可返回。

## 5. 代码编辑与文件操作

### 5.1 手机编辑器

- 浏览时默认阅读模式，用户主动进入编辑模式，降低误触风险。
- 编辑支持自动缩进、括号补全、撤销重做、查找替换、多行选区缩进 / 反缩进、触屏符号快捷栏。
- 键盘弹出时当前光标仍可见；自动折行默认开启。
- **自动存手机草稿，手动保存到电脑原文件**。未保存状态、保存中、已同步、冲突需明显区分。
- 尽量保留源文件的编码与换行符格式；遇到二进制或不支持格式则提示，避免损坏文件。

### 5.2 文件管理范围

| 已纳入 | 本期不做 |
|---|---|
| 新建文件、新建文件夹 | 文件 / 文件夹移动 |
| 编辑和保存已有文件 | 文件 / 文件夹重命名 |
| 删除单个或批量文件及目录 | PyCharm 级项目重构 / 重命名引用 |
| 编辑撤销、历史快照、删除恢复 | 自动修改代码引用关系 |

- 文本编辑撤销应支持当前编辑会话；已保存到电脑的内容可通过历史快照恢复。
- 删除的文件和目录默认进入电脑端 PocketCode 专用回收区；支持跨会话恢复，避免误删造成不可逆后果。
- 清空回收区等不可恢复操作应单独确认；恢复机制不可用时不能默默永久删除。

## 6. 离线缓存与多版本草稿箱

### 6.1 两种缓存策略

| 缓存模式 | 默认行为 | 离线能力 |
|---|---|---|
| 按需缓存（默认） | 打开过的文件自动缓存 | 浏览、搜索和编辑已缓存文件 |
| 整项目缓存（可选） | 缓存项目目录树及选定范围内的源代码 | 离线浏览、搜索和编辑所缓存项目 |

- 每个项目独立选择缓存策略；提供缓存大小、最近更新时间、刷新与清理入口。
- 整项目缓存应跳过大型依赖、虚拟环境、构建产物和二进制文件；默认排除常见密钥、凭据与敏感文件，允许用户在安全提示下调整范围。
- 重连后优先增量更新，自动刷新普通缓存；**不能覆盖用户的草稿**。
- 缓存清理与草稿清理必须分离；离线只能看到最后一次成功缓存的版本，不能标成“电脑最新”。

### 6.2 草稿箱核心规则

- 支持多个文件，每个文件支持**多个独立副本**，可自由命名，例如「异常处理实验 A」「随便改着玩」。
- 草稿可以从缓存文件、电脑文件或其他草稿创建；可以离线修改、比较、重命名草稿及主动删除草稿。
- 保存草稿不等于同步到电脑；**重新连接不自动提交草稿**，由用户自行决定何时同步。
- 草稿可与电脑当前版本、缓存基线或其他草稿比较，支持差异查看。
- 草稿也能走「给哥哥看」的任何分享模式，分享内容必须标注「草稿」与其来源版本。
- 应提供导出 / 备份草稿的能力；浏览器存储与应用数据并非永不丢失，不能以“自动保存”暗示永久安全。

### 6.3 保存冲突与恢复

- 编辑开始时记录来源版本；正式写入前，电脑服务重新检查原文件版本，避免覆盖其间来自 PyCharm / Codex 的修改。
- 冲突时展示「电脑最新版 / 手机草稿」的差异，并允许：保留草稿、手动合并、明确确认后覆盖、另存为新文件。
- 用户选择覆盖前必须提供可恢复的电脑文件快照；失败时不得丢失草稿。
- 自动更新不等于自动合并：即使能重新连上电脑，也不能擅自写回未保存草稿。

## 7. Python 代码理解与错误提示

- 首版支持常见语言的基础高亮；**语法诊断优先 Python**，不追求马上达到 PyCharm 的全部能力。
- Python 诊断目标：语法 / 缩进错误、常见未定义名称与导入问题、可识别的类型问题、部分代码规范提醒。
- 错误显示红色波浪线、警告黄色波浪线；用户主动查看诊断提示、定位来源和解释。
- 在线时可利用电脑上的 Python 分析工具检查未保存的手机草稿，不要求先写入电脑文件。
- 电脑离线时尽量保留手机端可实现的基础检查；依赖项目环境的深度诊断明确标注暂不可用。
- 工具不得未经允许自动改代码；自动修复（若实现）需预览并由用户决定应用。
- 推荐技术候选包括编辑器诊断接口、Ruff、Pyright、Tree-sitter / 语言服务器；具体组合交由实现阶段验证。

## 8. 「给哥哥看」：智能代码分享

### 8.1 五种分享模式

| 模式 | 用户操作 | 分享内容 |
|---|---|---|
| 片段 | 选中代码 → 复制 / 分享 | 代码 + 文件路径 + 行号 |
| 单文件 | 选择文件 → 系统分享 | 原始文本文件或可阅读内容 |
| 智能关联 | 选中函数 / 文件 → 分析建议范围 | 当前代码、相关定义 / 引用、结构摘要及可选关联文件 |
| 多文件 | 勾选多个文件 → 分享 | 保留相对路径的上下文文件；必要时临时 ZIP |
| Git Diff | 选择工作区变更或提交差异 | Diff、文件列表、可选上下文 |

- 支持附带精简项目结构树、模块关系、函数定义与调用关系；文件路径、来源版本、语言、行号要明确。
- 分享前显示将发送的文件清单、总大小、草稿 / 电脑版本标识及敏感数据提示，可取消勾选。
- 智能关联优先让程序推荐，不自动无限扩张；动态导入、运行时反射等无法识别的关系应如实标注。
- **分享草稿**与分享磁盘原版都被支持，默认明确标识来源，避免 AI 理解错版本。

### 8.2 分享方式与临时文件

- 小片段优先复制文本；单文件尽量直接系统分享；多文件默认优先生成便于阅读的上下文文档。
- ZIP 作为可选方案：在电脑整理内容，手机仅在应用私有临时目录缓存，不把压缩包堆在公共下载文件夹。
- 分享后或超过合理保留期限清理 **PocketCode 自己创建的临时文件**；必须保证接收方读取完成前不提前删除，且无法替其他应用删除其已接收的附件。
- ZIP 能否作为目标 ChatGPT 客户端的可读附件，需要实测确认；若不支持，回退文本包或原始文件分享。

### 8.3 AI 直接读取及修改：长期目标

- 理想：在现有 ChatGPT 对话中，用户一句话指定文件，AI 可以按需列目录、读文件、搜索代码、查看 Git Diff。
- 更进一步：AI 生成补丁，用户在 PocketCode 预览 Diff 并明确授权后，由电脑服务应用，并支持恢复。
- 该能力是否可用依赖 ChatGPT 当前平台、套餐、连接器 / MCP 支持及远程访问方式，**不得把自建 MCP 等同于普通 Android 聊天立即可用**。
- 即使直连不可用，仍需提供手动分享，以及后续可选的「导入 AI 生成的补丁 → 校验 → 预览 → 确认应用」。
- 基于最低权限：优先只读授权，写操作必须经过授权、版本检查和确认；不能给 AI 整台电脑的任意文件访问权。

## 9. Git 与代码差异

- 本地展示当前分支、未提交修改、暂存区与工作区 Diff；分享 Git 差异不要求推送或提交 GitHub。
- 支持查看某个文件与其草稿 / 缓存 / 电脑当前版本的差异。
- 首版不需要实现 Git push、复杂 rebase、force 操作，也不承担 IDE 的完整重构能力。

## 10. 安全性、可靠性与边界

- 默认只允许手机访问电脑上**显式授权的项目 / 工作区根目录**，拒绝越界路径及通过符号链接绕过目录边界的访问。
- 手机配对后才能访问；提供撤销授权。服务默认仅面向局域网，不暴露公网或开放无认证接口。
- 所有文件写入、删除、覆盖都必须有权限校验和可解释的失败提示；持久草稿不应因网络失败丢失。
- 分享时排除常见敏感内容并让用户预览，避免误传 `.env`、私钥和访问令牌；日志不记录凭据或完整代码正文。
- 手机本地缓存、草稿需支持清理、导出和存储空间管理；APK 离线启动和持久化需要实际设备验证。
- 大文件、二进制文件、无法解码的内容和文件权限错误要明确处理，不可静默损坏原文件。

## 11. 视觉与交互原则

- 以手机单手使用为先：页面简洁、操作可触达、视觉层级清楚；不照搬桌面 IDE 的多面板布局。
- 默认 GitHub 式文件浏览；可切换树状浏览。
- 默认视觉折行；全屏阅读 / 编辑；顶部文件名打开「已打开文件」抽屉。
- 导航操作要求主动触发，防止误触；底部弹层适合选择大纲、操作菜单、已打开文件。
- 区分在线、离线、读取缓存、草稿未同步、冲突、保存成功等状态，避免让用户猜测文件是否真的写入电脑。
- 主题支持深色 / 浅色；尊重字号与行距设置。

## 12. 分阶段交付建议

| 阶段 | 交付重点 | 阶段验收 |
|---|---|---|
| M0 · 最小闭环 | Windows 独立程序与文件服务、Android APK、手机热点连接、授权项目、目录浏览、打开文件 | 无 GitHub 的真实代码能从已配对手机 APK 读取；电脑修改后刷新可看到最新保存内容 |
| M1 · 可日常使用 | 自动重连与更新、编辑、新建删除、撤销恢复、离线缓存、草稿箱、基础分享 | 手机可修改电脑文件；断线后可看缓存、维护多份草稿，重连不丢内容 |
| M2 · 更顺手的工作台 | 搜索、大纲、符号导航、Python 诊断、多文件抽屉、Git Diff、丰富分享 | 多文件阅读、语法问题定位、分享代码上下文可用 |
| M3 · 高阶能力 | 智能关联、跨文件关系、导入补丁、条件允许时 ChatGPT 连接 | 关联结果可核验；AI 读写必须经能力实测与权限审查 |

**实施原则：** 先解决第一优先级，再逐步兑现第二、第三、第四项；不为了赶功能数量而削弱文件安全性和实际可用性。多个 GLM 对话可以分模块开发，但应先有统一共享接口和可运行的最小闭环。

## 13. 关键验收场景

1. **无仓库推送：** 电脑修改并保存 `react_agent.py`，未执行 Git commit / push；手机连接后能读取最新磁盘版本。
2. **自动发现：** 电脑在授权工作区新增项目或文件；手机下次连接自动更新列表，手动刷新也有效。
3. **手机保存：** 手机编辑一个 Python 文件，明确保存后电脑原文件发生对应变化；保留原始换行和编码。
4. **防止覆盖：** 手机上有未保存草稿，电脑端同时修改原文件；手机收到冲突提示，不自动覆盖任何一边。
5. **离线多草稿：** 断开电脑，打开缓存文件，创建并保存两份不同草稿；重新打开手机应用仍可找到它们。
6. **重新连接：** 联网后只更新缓存，草稿不自动写回；可以看 Diff 并选择同步或继续保留。
7. **撤销删除：** 删除一个文件后，关闭并重启应用，仍可从回收区恢复。
8. **导航不误触：** 普通点击符号不会跳文件；长按选中并选择「跳转定义」才执行，可返回原位置。
9. **视觉折行：** 手机折行显示超长代码，不向电脑原文件插入换行，逻辑行号不变。
10. **Python 诊断：** 对可识别语法错误显示红色波浪线、诊断信息；没有电脑时明确显示能力降级。
11. **分享草稿：** 能将草稿中的片段、文件或 Diff 连同来源路径 / 行号分享给 ChatGPT，不误标为电脑最新版。
12. **安全范围：** 未配对手机和授权目录以外的路径无法读取或修改；敏感文件默认不参与分享。
