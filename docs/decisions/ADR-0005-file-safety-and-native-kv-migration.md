# ADR-0005：文件一致性、目录边界与原生 KV 兼容迁移

状态：已采用，2026-10-26。

## 背景

审查发现目录扫描、Git、回收区恢复没有统一落实授权根边界；手机保存响应
错误确认后续输入；Android 直接把百分号编码后的逻辑 key 当作文件名，
拒绝特殊字符和长路径。修复范围是现有行为，不增加产品功能。

## 决策

- 扫描目录元数据和搜索时跳过符号链接和 Windows 重解析点，并复核真实路径。
  显式单文件访问仍保留 path_guard 对根内链接的既有规则。
- Git 使用 literal pathspec、NUL 分隔状态；状态范围限制在授权目录，输出
  转换为授权根相对路径。禁用外部 Diff 和 textconv。
- 回收区按物理存储根共享进程内事务锁。恢复按当前 project_id 与原相对路径
  重新授权，不把历史 source_abs 当作权限证明。
- 文件响应的正文、长度和 hash 取自同一份原始字节；保存完成临时文件刷盘后，
  在替换前再次复核目标位置与版本。
- 电脑缓存只记录实际发送并得到确认的正文；草稿保留保存期间的新输入。
- Android 逻辑 key 和 TS API 保持不变，物理文件名变为 `kv2-<sha256(key)>`。
  记录使用 PCK2 标记、Java writeUTF key、UTF-8 value，自带原始 key，支持无外部
  索引的按前缀枚举。写入使用同目录临时文件、fsync、原子移动。

## 兼容与合同

旧 key 文件仍可读取/枚举；先成功写入新记录，才移除对应旧文件。升级不批量
清空草稿或缓存。新版本不保证旧 APK 能读取升级后的记录，回退 APK 前应备份。

接口字段与错误码不变。合同显式补充 Git Diff/回收区恢复的 PATH_FORBIDDEN
403，以及恢复时项目已移除的 PROJECT_NOT_FOUND 404 语义；同步错误 fixtures、
后端响应说明和客户端测试。客户端已有通用错误解析，不需要新增类型字段。

## 保证边界

保存仍是乐观并发控制。最终版本复核与文件替换不是跨进程 compare-and-swap，
不能宣称完全锁住 PyCharm/Codex 等不参与协议的外部写入。回归用例覆盖快照和
刷盘期间发生修改的窗口，但不把通过测试说成任意调度下的绝对原子保证。

扫描不跟随链接的策略会隐藏根内目录联接的重复入口，以避免循环和重复扫描。
原生 JVM 测试验证实际 Java 仓储，APK 真机升级与持久化仍应单独验收。
